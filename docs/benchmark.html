How to read this

Attacks succeeded counts attack calls the agent actually made that reached a tool and returned success. Attacks attempted counts how often the model took the bait at all. The model attempted 47 of 62 attacks without Warden and 45 of 62 with it. A model that ignores an attack scores well without the guard doing anything, which is why both numbers are published.

Latency is per tool call, measured on one machine over loopback, so it is a floor rather than a production figure. Receipt bytes per call is the exported signed log divided by calls; most of it is post-quantum signatures.

What this does and does not show

Shown
  • Attacks that succeed against an unguarded agent are refused when the same calls pass through Warden, and every refusal is written to a signed, hash-chained log that verified.
  • Benign work still completes: 20 of 20 tasks with the guard in place.
  • The cost is visible and small: a few milliseconds per call and a few kilobytes of evidence.
Not shown
  • Model results vary between runs. These come from 2 full passes of one model; they are measurements, not a guarantee.
  • The guarantee is the deterministic gate (warden-gate), where a scripted agent makes every attack call and Warden must refuse all of them.
  • Warden stops calls its policy forbids. A policy that permits an action permits it whoever asked, so these numbers describe this example policy, not every deployment.
  • Tools and secrets here are synthetic, and everything runs on one machine.

Reproduce it

printf "FROM qwen3:30b-a3b\nPARAMETER num_ctx 16384\n" > Modelfile
ollama create qwen3-warden-ctx16k -f Modelfile
uv run --project agent warden-bench \
  --adapter openai-compatible --base-url http://127.0.0.1:11434/v1 \
  --model qwen3-warden-ctx16k --repeat 1
